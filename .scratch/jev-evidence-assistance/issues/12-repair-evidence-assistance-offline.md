## Bounded work

Use wayfinder and TypeSafe. Follow the repository's package-skill policy before using installed libraries. Preserve the original experiment branch, frozen questions, policy, corpus, native responses, ledger and saved demonstrations. Work in a separate isolated local experiment branch/worktree with fake transport and dummy credentials. Record the exact code commit and changed versions. Reuse the existing evidence only as disclosed development/regression material.

1. Isolate location failures. A malformed or degenerate Box makes that target's location unavailable, without discarding independently valid category, readability, presence or comparison inputs. Preserve strict validation of those answers and stage-wide failures such as unknown usage, wrong model, unreadable responses or invalid request scope. Keep null Box confidence as null; it alone cannot fail unrelated judgments or authorize an overlay. Verify behavior using retained response replay and fake transport, without contacting Jev.
2. Prepare stronger location safeguards for complete target containment, competing/repeated values and cross-page conflicts. Include the observed clipped amounts and falsely single repeated-name case as explicit regressions. A high presence, single-occurrence or Box confidence is insufficient by itself. Do not claim that padding, changed wording, a new check or suppressing every overlay establishes safe, useful model behavior. Document the proposed method, its limits and what fresh inference must test. Preserve named page-level source inspection when a location is unavailable.
3. Prepare versioned candidate questions and display rules covering Arabic and English category, all three readability descriptions, all five per-field support outcomes, presence, multiplicity and location. Retain independent field presence versus value agreement, uncertainty, missing declarations, reporting-period checks and explicit partial coverage. Numeric cutoffs may remain marked as awaiting development measurements; do not invent calibrated thresholds or tune on previously opened held-out answers and call them fresh validation.
4. Construct and inspect the actual complete four-page comparison request with the intended full-page rasters and maximum relevant fixed question suite. A Box-only failure must not silently drop an otherwise usable page. Enforce the existing four-page/five-attempt, question/target, resource and deadline bounds. Exercise encoding, page association and overflow handling offline. Do not enable long context, crop, downscale after failure or add a verification call beyond the selected contract. Offline transport checks do not establish provider context fit.
5. Produce a bounded revalidation proposal that the next decision can accept or revise. Identify candidate development cases, genuinely unopened held-out source families, task/language/outcome cells, a full four-image comparison, model-quality and timing observations, human-label checks, freeze order, attempt accounting and cost/stop bounds. Separate a small repair-feasibility check from any work needed to establish the existing broader release gates. Every replacement, failure, capture and uncertain dispatch must fit the proposed cap. This proposal authorizes no dispatch.
