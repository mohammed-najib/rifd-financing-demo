## Deterministic numerical proposal

Each cell retains exact language/slot/target/task/outcome. Category uses the selected native confidence; readability uses a unique winning native level mass, preserving fractional Score separately. Presence uses Noul or its complement, multiplicity the selected probability, support the selected confidence, and verification its appropriate Noul/complement. Native null Box confidence remains null and is never a numerical gate.

`extractObservations` extracts values from frozen native snapshots. Independent labels provide truth, relevant alternatives and bound region checks, never numeric scores. Real selection requires signed independent human native-outcome review. Standalone probes may contribute primitive observations but are excluded from automatic-chain display/coverage metrics. Repeats and derivatives retain all observations within the same canonical source family. Every family has total weight one per metric, shared across its items and repeats. Template/layout/generator/font groups remain visible and do not prove new-layout generalization.

A cell needs at least five independently checked families, at least one positive and every relevant negative alternative before attempting selection. Category requires each other category, readability each other level, support each other relation, presence its inverse, multiplicity its other classes, and each verification judgment its named failure. Missing evidence leaves that exact cell unset. This stricter explicit alternative rule is a proposal for review, not proof of the release targets.

Candidates are unset, 0, 1 and distinct observed native values, sorted numerically. Eligibility uses exact JavaScript `value >= floor`, with no rounding or equality tolerance. The selector enumerates the Cartesian product in exact sorted cell-key order and replays the shared complete policy for each combination. That preserves interactions between page usability, independent presence, period-first support, missing declarations, scoped conflicts, full coverage, uniqueness and all six bound checks.

For every candidate, retain family-weighted and raw denominators, displayed count, errors, correctness, harmful outputs and useful coverage separately by language. All predeclared full-run findings/highlights, including suppressed and failed ones, stay in the denominators. Missing adjudications fail selection. The proposal requires zero observed harmful findings/overlays, at least 95% displayed category/support correctness, 85% readability correctness and zero observed unsafe displayed highlights. An empty displayed denominator is undetermined, never a passed release gate. Useful findings include category, readability and support; useful highlights are tracked separately.

Optimization is lexicographic: maximize worst-language useful-finding coverage, worst-language useful-highlight coverage, summed finding coverage, then summed highlight coverage. Exact ties prefer stricter cutoffs by sorted cell key; unset sorts above 1. Retain the selected index and every candidate's cutoffs and metrics. Coverage release goals remain 70% useful findings and 60% useful highlights separately by language. Selecting a partial policy does not waive a missed goal.

The exhaustive search has a reviewable 20,000-combination and 30-second computation limit. It returns no incumbent and leaves every cutoff unset if enumeration or time is exhausted, meanings are incompatible, checked labels are incomplete, evaluation evidence appears, or no combination qualifies. It does not switch to a greedy search or pool cells. A search that cannot complete requires a new explicit procedure decision. The clearly fabricated demo selects 0.95 only for its invented fixture. That number is neither a product recommendation nor a validated cutoff.

## Timers and stronger stops

The reviewed runner starts the absolute monotonic server deadline before authorization/account checks and frozen-manifest preflight. File reads receive cancellation and bounded hashes recheck the deadline. The supervisor inherits that deadline before bounded input copies and worker startup; direct offline calls start it on supervisor entry. It includes admission, source/raster hashing, context/plan construction, crop work, request metadata/preflight, SDK encoding, durable dispatch marking, transport/response parsing, mapping, policy composition and normal ledger closure. It clamps to 45 seconds. Blocking decoding/encoding runs in terminable workers; the parent supervises attempt and crop deadlines while those workers execute synchronously.

An attempt's absolute eight-second deadline starts before bridge preflight/hashing/encoding, covers SDK construction, durable marking, transport and native response validation/mapping, and is clamped to the remaining server budget. Post-response ledger reconciliation writes belong to the server boundary. Checks occur after durable dispatch marking and again at the supervisor immediately before transport. A durable mark followed by cancellation remains counted uncertain dispatch. Transport receives an actual abort signal; worker termination stops local synchronous work. Provider cancellation/refunds are not established.

Each crop page keeps the eight-second preparation bound and the cumulative crop-work limit remains 20 seconds, enforced by remaining absolute budget rather than checking only after overshoot. Earlier browser raster preparation has separate eight-second page/20-second run limits and recorded transforms. It is outside this prepared-input server timer. Bounded supervisor copies are limited to 5 MB original plus 8 MiB rasters and bounded metadata; they are measured and checked before handoff. Hard OS memory/CPU limits, browser decoder allocations, upload time and representative mobile/deployed scheduling remain deployment resource/performance gates. JavaScript timers do not prove a real-time OS guarantee.

On deadline/cancellation the supervisor aborts active transport and terminates workers. Cleanup waits are bounded by the remaining server deadline. Best-effort metadata cleanup may finish afterward; a durable uncertain mark or stale lock remains a stronger stop. The reviewed runner also stops in memory after an execution failure. Unknown accounting, interrupted locks, access/resource failures, exceeded token bounds and deadlines never become ordinary location-only suppression. A verification answer failure suppresses affected locations while independent valid findings survive.
