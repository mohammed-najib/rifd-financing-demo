## Transfer and recovery

Eligible Under review applications assigned to Salma offer a bilingual simulated
reassignment control on the review, correction-request and decision screens.
The existing transfer transaction records Khaled's assignment, an identified
simulated internal event, shared revision and receipt together. A simulation
has a distinct receipt fingerprint from a normal transfer. It preserves status,
submitted information, assessments, checks, correction rounds and notes.

Only the initiating screen holds its displayed snapshot. Other tabs receive
the transfer through normal synchronization, including activation checks.
Public reads always return current data. Every stale staff-write family fails
without a receipt, activity, notification or proposed application effect.
Readable staleness precedes lost-assignment denial; inaccessible records remain
unavailable and expired sessions fail before protected access.

Load latest reveals Khaled and the simulated transfer. Note, replacement,
correction-target and decision text remain unapplied and read-only. Confirmed
reclaim advances the revision again, requiring explicit inspection before a new
action. This gate also applies when the refused action has no text to retain.
Final decisions require a newly prepared confirmation. Expiry retains work for
the same identity, rechecks access and never replays a write or confirmation.
Pending simulations participate in departure handling; lost acknowledgements
require inspection.

## Verification

Tests use the accepted public Demo interface with actual IndexedDB and the
production-screen seam. The first red interface test reproduced the absent
simulated transfer. The first red screen run reproduced the absent control.
Focused checks cover all eleven stale staff-write variants, simulation
eligibility, stale/forbidden/expired precedence, storage rollback, receipt replay
and fingerprint misuse, uncertain completion, a separate real same-context
transfer/note race, and confirmed reclaim with a new explicit action.

Screen journeys cover retained notes and replacement reasons, other-tab updates,
correction reasons, decision reasons through expiry, renewed final confirmation,
uncertain simulation recovery and control visibility. Keyboard activation,
Escape focus restoration and overflow checks run alongside the recovery journey.
The final-decision test initially sent Enter before asynchronous inspection
enabled its button; it now waits for the permitted action.

The full pure-domain suite passes all 105 cases, and both skill checks pass.
Typecheck, lint and the production build pass. The build retains its existing
large-client-chunk warning.
The complete public-interface suite passes all 118 cases.

All 381 unique production-screen cases have passing results, 127 each in Chrome,
Firefox and WebKit. All 24 new stale-write cases pass across those engines.

the remaining 248. The existing Arabic Firefox interrupted-preparation test

no unapplied text, Load latest cleared the intent and reclaim re-enabled writes

dirty text, including background assignment updates and same-identity expiry.

fix and found no other gap or scope creep.
